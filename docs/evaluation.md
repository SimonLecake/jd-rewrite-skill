# 评估方法与证据边界

[返回首页](../README.md) · [English overview](../README.en.md#results)

本项目衡量的是 AI 输出与经确认业务标准的一致程度。人工判断是需复核的业务参照，不自动等同于客观正确性；有争议的标签应先澄清再用于标定。

## 已记录的结果

| 记录 | 来源 | 可支持的结论 | 未公开或未验证的部分 |
| --- | --- | --- | --- |
| 55% → 70% | 作者作品集的 Project 1 影响说明 | 特定业务评估场景报告提升 15 个百分点 | 原始样本、样本量、评估窗口、模型配置和逐例日志 |
| 100% 样本内对齐 | 同一作品集的标定样本说明；Skill 回测要求 | 选定历史案例上的修正规则可达到样本内对齐 | 对新岗位、新简历、独立留出集的泛化能力 |
| 约 50% → 58% | Skill v4.1.0 核心认知 9 与 Prompt 模板 | 数字人岗位中去数值刻度的局部观察 | 与 55% → 70% 不属于可直接合并的同一实验；未提供可复现日志 |
| 一致率 ≥85%，错误复发率 <10% | Error Case RAG 闭环设计 | 未来验证目标 | 目标尚无已完成实现或结果支撑 |

以上数字均为来源材料中的记录或目标。本次公开整理没有重新运行企业评估服务，也没有生成新的测量结果。

## 标定与验证应分开

现有 Skill 要求调试样本达到 100% 一致。它也允许从全部为人工通过的历史误拒案例启动标定。这类样本适合定位假阴性，但不能衡量错误通过率，也不能代替完整分布的验证。

建议后续采用以下验证流程；这些是评估方案，不是本仓库已自动实现的能力：

1. **冻结初始条件：** 记录原 JD、模型版本、调用参数、输入字段限制和规则版本。
2. **复核标签：** 保留人工结论及证据理由，对分歧标签再次确认。
3. **按来源拆分数据：** 标定集用于改规则，留出集用于最终评价；同一候选人或高度相近样本避免跨集合泄漏。
4. **覆盖正负样本与边界：** 包含人工通过、人工拒绝、可迁移经验、信息缺失和历史高频误判类型。
5. **控制变量对比：** 在同一评估集上比较原 JD、结构化规则、去刻度 Prompt；接口具备后再加入 Error Case RAG。
6. **重复调用：** 检查同一输入结果是否稳定，避免把随机波动当作效果提升。
7. **留存证据：** 记录实际传给模型的内容、输出、人工标签和错误归因；报告分母与样本分布。

## 指标定义

| 指标 | 建议计算方式 | 用途 |
| --- | --- | --- |
| 人机一致率 | 与确认人工结论一致的样本数 / 已评估样本总数 | 总体对齐情况 |
| 错误拒绝率 | AI 拒绝但人工通过的样本数 / 人工通过样本数 | 检查是否误拒合适样本 |
| 错误通过率 | AI 通过但人工拒绝的样本数 / 人工拒绝样本数 | 检查是否因放宽规则引入新错误 |
| 重复调用稳定性 | 多次调用中判定一致的样本比例，并报告次数 | 测量输出波动 |
| 错误复发率 | 对已修正规则适用的新样本中，同类错误再次出现的比例 | 验证修正规则是否持续生效 |

原始闭环方案提出错误复发率目标，但未固定分母。正式实施前应约定观察窗口、适用样本范围、规则版本和“同类错误”的定义；不能只记录复发次数而忽略处理量。

## 需要继续验证的问题

- 人工标准本身是否一致，是否以岗位所需能力及可验证证据为依据？
- 数值刻度与定性规则各自在哪类模型上更稳定？
- JD 输入在下游结构化、压缩或截断后，哪些规则实际保留？
- 多个纠正规则发生冲突时，是否有可解释的适用范围和优先级？
- 修正已知误拒后，错误通过是否上升？

公开示例仅帮助理解规则表达，不包含真实候选人评估结果，也不提供自动化招聘决策服务。
