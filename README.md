## 先看一个例子

同一句“优先”，HR 理解为加分项，模型却可能把它当成拒绝条件。本项目把隐含的判断边界写进规则。

| 原始 JD | 标定后的规则 |
| --- | --- |
| “知识库项目经验优先” | 该经验是加分项，**不得因缺少它直接否决**。 |
| “掌握 Markdown、Notion 等工具” | 工具名称仅为示例，**使用其他工具完成同等任务也可作为能力证据**。 |

*人工编写的说明性示例，非模型实测输出。* [查看完整输入与双框输出 →](examples/jd-before-after.md)

## 为什么使用它

面向 HR、AI 评估运营和供应商标准制定者，尤其适合**模型权重与系统 Prompt 冻结、只能编辑 JD 输入**的场景。

- **减少规则误读**：把硬门槛、加分项、经验档位与等效能力分清楚，覆盖 17 类已整理的误判模式。
- **统一执行口径**：同一套业务标准，分别生成给人工使用的加权细则和给模型使用的双框文本。
- **让调整可以检验**：有样本时做标定和回测；无样本时明确标记“待回测”，让分歧成为下一轮修改的依据。

## 如何工作

```mermaid
flowchart LR
    A[JD 与可选历史样本] --> B[误判诊断]
    B --> C[规则标定]
    C --> D[人工细则 + 模型双框文本]
    D --> E[样本回测与人工确认]
    E --> C
```

**有样本 → 标定模式：** 从带人工判断的样本中提炼能力证据、档位和边界，交付细则、回测表和双框 Prompt。Skill 建议至少 5 份作为启动材料；独立效果验证需要另设留出集。

**仅有 JD → 改写模式：** 诊断歧义，生成默认规则与双框 Prompt，标记为待样本回测。

一个关键取舍：**人工细则保留数值权重，模型输入默认采用定性档位**，避免强塞的数值刻度与模型已有打分习惯冲突。[设计依据与完整工作流 →](docs/design.md)

## 快速使用

**1. 获取。** [下载 Skill 包](jd-eval-calibrator%20%282%29.skill)，导入兼容宿主；也可浏览 [源码目录](jd-eval-calibrator)。需要宿主提供 LLM、文件读取与文档生成能力，具体安装方式取决于宿主。

**2. 提问。** 提供 JD，即可从改写模式开始：

```text
请用 jd-eval-calibrator 改写以下 JD：
指出可能被 AI 误执行的要求，生成评估细则，
并分别输出“岗位职责框”和“岗位要求框”的文本。
没有历史样本，请标记为待回测。

【JD】在此粘贴岗位职责和任职要求。
```

**3. 验证。** 将两段文本填入既有评估工具对应的输入框，用授权且脱敏的已确认样本试跑、核对分歧。最终业务判断由人工负责。

**你会得到：** 修订 JD、评估细则文档与两段可复制的输入文本；标定模式还提供样本证据矩阵和回测表。文档导出取决于宿主工具。
