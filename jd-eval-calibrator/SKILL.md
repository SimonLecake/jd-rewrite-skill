# JD评估校准器（jd-eval-calibrator）

## 核心定位

AI简历评估准确率低时，默认归因路径是改模型。本skill处理的是另一条路径：**模型侧冻结，只改JD文本**。JD的读者本质上不是人、是模型——人类HR能理解"优先""相关专业""从业经验"的弹性，模型会将其执行为一票否决、穷举白名单、绝对前提。把JD从"写给人看"改写为"写给模型执行的评分程序"，即可在不动模型的情况下对齐AI与人工判定。

## 十条核心认知（来自实践的误判机理）

1. **"优先"会被模型执行为门槛**。JD中所有"优先/优先录取/加分"表述必须显式声明为加分项，并写明"不得作为否决依据"。
2. **示例列表会被模型当穷举白名单**。"音乐学、作曲等相关专业"会被执行为仅这4个专业合格。专业/技能/经验枚举必须改为开放式（"含但不限于"+认定总表），或显式声明"以下为示例非穷举"。
3. **经验要求会被绝对化**。"有X经验"被理解为无X经验即拒绝。必须改为梯度档位（有直接经验/相关经验/无经验各给多少分），且声明实习、项目、外包、兼职与全职等效。
4. **模型无法自行处理非典型背景**。跨界学历（本科非相关+硕士相关）、海外院校、独立学院、大厂外包/驻场、在读应届——每一类都必须给出显式归类规则，否则一律误杀。
5. **无样本不回测，细则不可信**。有简历样本时必须回测：全部人工通过样本应达到通过线，且分数排序符合业务直觉。不回测的权重是猜测。
6. **简历"求职意向"字段会被模型当匹配判据**。候选人在简历中写的求职意向（如"人力资源""音乐教师"）与本岗位名称不一致时，模型会判定"意向不匹配"而否决。必须在禁令中显式声明：求职意向仅为候选人偏好参考，不得作为否决依据，按实际能力与经历评分。
7. **低档经验会被模型当作"无经验"**。当候选人只有C档经验（如音乐教学、演奏、平面设计）而无S/A/B档经验时，模型倾向于判定"无相关经验=0分"而非按C档给分。必须在经验维度中显式写明：C档经验是15分而非0分，教学/见习/代课/短期经验（哪怕仅1-3个月）也按C档给分，不得判"无经验"。
8. **专业认定与经验认定会被模型耦合执行**。当候选人专业完全不相关（如空管、交通、智能科学）但有S档直接经验（多模态评测/数据标注）时，模型在门槛阶段就因"专业不符"否决，根本不进入经验评估。必须在门槛规则中显式声明：专业认定与经验认定独立执行；有S档直接经验的候选人不论专业名称均按豁免档进入评分流程，不得在门槛阶段因专业否决。同时，休学/复读/延毕/五年制本科属正常学制变动，不得视为异常。
9. **显式数值刻度会与微调模型的打分先验冲突，反而降低一致性**。当评估模型已针对性微调、对"打多少分"有强训练先验时，prompt里硬塞一套数值刻度（维度分值、S=40/A=32、≥60通过线）会与模型先验对抗，产生冲突噪声：同一简历多次跑分数飘忽、档位边界摇摆、自相矛盾，一致性反而比不给刻度时更低。**实测验证：数字人岗完整刻度版prompt与人工一致率约50%，剥离数值刻度、仅保留定性档位认定+门槛+禁令+few-shot的精简版提升到58%。** 因此网页端prompt默认应采用"去刻度精简版"：保留经验档位定性归类（S/A/B/C各档"算什么"，不写分值）、硬性门槛、认定规则、禁令、判定样例；判定规则改为定性（S/A档→通过；B/C档且有相关支撑→通过；两项均无→不通过），不做分数累加、不写数字通过线。注意：数值刻度在细则文档（给人和供应商看、作重训标注规范）中仍保留，仅从喂给模型的prompt中剥离。
10. **相关性判断会用关键词匹配代替能力判断，导致可迁移性评估双向失准**。模型不锚定岗位核心能力，而是做简历关键词与JD关键词的字面重合度匹配，由此在两个方向同时出错：**过度乐观**——把泛背景等同为核心胜任力（如把音乐混音、游戏音效、影视配乐等"泛音频"经验直接等同于TTS录制监棚胜任力）；**过度保守**——把高度可迁移的经验判为"零相关"（如把配音导演、ADR指导、录音助理、棚内录音工程等与TTS监棚在"棚内作业/音频质量把控/发音与声学判断"上高度同构的经验判为零分）。本质是缺乏对"岗位到底要什么能力"的精准锚定。纠正方法（prompt侧）：①在评估导引与经验档位中先用一句话锚定岗位核心能力（不是关键词，是能力内核，如"TTS监棚=棚内录制流程把控+发音/声学质量判断+音频交付标准把控"）；②给出**双向陷阱清单**——明确列出"看似相关实则泛化、不得等同核心胜任力"的背景（治过度乐观）和"看似不相关实则高度可迁移、不得判零"的背景（治过度保守）；③要求模型按"能力内核是否同构"判断档位，而非按关键词是否命中。详见误判模式#17。

## 输入与模式路由

收到任务后先判断模式：

**标定模式**（首选）：输入 = JD + 带人工判定结果的简历样本（≥5份，通过/拒绝均有更佳）。执行下方"标定模式工作流"。

**改写模式**：输入 = 仅JD。执行"改写模式工作流"。

样本可以是"人工全通过但AI全拒绝"（纯假阴性标定，最常见），也可以是混合判定。若用户只给了JD但暗示有样本，主动询问是否有已有人工判定结果的历史简历。

## 标定模式工作流（5步）

1. **解析样本**：逐份读取简历（图片型PDF用视觉识别或渲染后读取，勿因文本提取失败放弃样本）。同时解析原JD，逐句标注其表述类型：硬性要求/弹性加分/开放式枚举（疑似穷举）/绝对化经验要求。
2. **结构化矩阵**：将全部样本按统一维度列表化——学历层次、院校、专业、经验类型、经验中是否含目标领域直接经验、作品/成果证明。矩阵是后续所有设计的证据基础。
3. **提炼共性与边界**：回答四个问题——实际门槛是什么（全员满足的最低标准）？区分度最高的维度是什么（权重最高者）？哪些维度全员达标、只配做达标性给分（压缩权重）？通过样本中最"边缘"的个案长什么样（决定豁免规则）？
4. **设计权重细则**：按 [references/rubric-design.md](references/rubric-design.md) 设计四维度权重、档位锚点与通过线。铁律：每个档位必须能映射回至少一个真实样本（"对应正样本"列），禁止凭空虚设档位。
5. **生成细则文档并回测**：按下方"输出文档结构"产出文档，用细则给每份样本打分并列表——全部人工通过样本须≥通过线（默认60），最低分与通过线之间须留≥5分安全余量；不满足则调整档位分值或通过线，直至一致率100%。

## 改写模式工作流（无样本，3步）

1. **诊断原JD**：按十条核心认知逐项扫描，列出所有会被模型误执行的表述。
2. **重写为四段式结构**：硬性门槛（可枚举、无歧义、任一不满足即拒）→ 权重评分（套用 [references/rubric-design.md](references/rubric-design.md) 的默认框架）→ 加分项声明（原JD中所有"优先"表述归位于此）→ 边界情形处理规则（应届/海外/跨界/外包的显式归类）。
3. **补齐同义词认定**：按 [references/misjudgment-patterns.md](references/misjudgment-patterns.md) 的模板生成专业认定总表与经验等效认定表。明确告知用户：无样本标定，通过线与档位分为经验默认值，上线后需用首批人工判定结果回测校准。

## 输出文档结构（默认九章）

标定模式产出完整九章；改写模式省略第二、八章并注明"待样本回测"。

1. **背景与反向生成逻辑**：为什么改写（误判机理），本细则的证据基础。
2. **样本共性分析**：结构化矩阵表 + 共性结论（标定模式核心证据）。
3. **修订版JD**：职责保留原文；任职要求重写为"硬性门槛（N条）+ 权重评分声明 + 加分项声明"。
4. **评估维度与权重细则**：每个维度一张档位表（档位/认定标准/得分/对应正样本），附执行要点。
5. **同义词与等效认定规则**：专业认定总表、经验等效认定表、工具技能关键词表——防字面匹配的核心武器。
6. **一票否决项与边界豁免**：允许模型直接拒绝的情形（极少）+ 禁止直接拒绝的情形（逐条给出正确动作）。
7. **误判模式清单与纠正规则**：从 [references/misjudgment-patterns.md](references/misjudgment-patterns.md) 选取本JD命中的模式，写成显式禁令。
8. **回测验证**：全样本打分明细表 + 一致率结论 + 分数区间解读（可用于面试优先级排序）。
9. **落地使用建议**：嵌入评估prompt的用法、打分明细作为few-shot正样本的用法、供应商执行标准、月度回测迭代机制。

## 同步产出：网页端双框prompt（必交付）

细则文档之外，必须同步产出两个可直接粘贴进网页端评估工具的prompt文本块，**双通道交付**：①在回复中以代码块形式呈现（方便直接复制）；②作为"附录：网页端双框prompt"一章收入细则docx（用浅灰底纹代码块排版，含使用方法与字数精简顺序说明），使文档成为一站式交付物。

- **岗位职责框** = 原JD职责照抄 + 一段"评估导引"（告知模型该岗位的核心交付物是什么、评估时应看重什么、不应看重什么）。
- **岗位要求框** = 硬性门槛 + 经验档位定性认定 + 判定规则 + 认定规则 + 禁令 + 加分信号 + 判定样例，从细则第二至六章浓缩而来。**默认采用"去刻度精简版"**（见认知#9）：经验档位只写"算什么"不写分值，判定规则用定性逻辑（S/A档→通过；B/C档且有相关支撑→通过；两项均无→不通过），不做分数累加、不写数字通过线——实测此版与人工一致率（58%）高于完整刻度版（约50%）。完整刻度版（含维度分值与≥60通过线）仅保留在细则文档中，供人工/供应商执行与重训标注使用，不喂给模型。

转化规则、字数砍削顺序、标定模式的few-shot样例写法、完整实例，见 [references/prompt-templates.md](references/prompt-templates.md)。第一章（背景）与第九章（落地建议）是给人看的，禁止放入任何输入框。

## 产出要求

- 交付docx：用docx skill（Create路线）生成，文件名格式`{岗位名}-JD反向生成与AI评估细则.docx`，附录章内置双框prompt（浅灰底纹代码块）。
- 同步交付双框prompt：回复中两个代码块（岗位职责框/岗位要求框），可直接复制进网页端；标定模式须在禁令后附2-3个一句式判定样例（few-shot）。
- 文档基调：写给"评估系统+供应商HR"双方读者，每一条规则都必须可直接执行，禁止"视情况而定""综合考虑"一类表述。
- 先在回复中呈现核心结论（误判根因、权重总表、回测结果），再交付文档与prompt。

## 边界与提醒

- 本skill只优化"筛选标准文本"，不承诺模型能力问题的解决（如模型读不懂PDF、提取信息失败）——发现此类问题要在文档中标注为"信息提取层问题，需工程侧解决"。
- 若用户表示模型侧可以调整（改prompt/fine-tune），细则的第三至七章仍可直接复用为prompt内容，第八章打分明细可作为训练标注数据——在落地建议中写明该用法，但不越俎代庖设计prompt。
- 通过线、档位分值上线后必须用新的人工判定结果持续回测（建议月度），在文档第九章固化该迭代机制。
